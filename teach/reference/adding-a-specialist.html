Adding a specialist

Seven decisions turn a cloned profile into a specialist with its own voice, its own room, and its own limits. Each decision has exactly one home. This page records the home, the value Torchwood used, and the trap that the decision hides.

This document grows one row for each lesson of Stage 4. A row appears only after a lesson has made that decision against a real machine. No row is written in advance.

Decision Where it lives Torchwood Trap
Bot credentials .env, key TELEGRAM_BOT_TOKEN A token from /newbot, with group privacy turned off --clone-from copies .env, so the new profile wears the identity of the old one. Replace the token as a separate step. The same flag also copies memories/, so run memory reset --target memory.
Model config.yaml, key model.default openai/gpt-5.6-luna A flash model is the wrong economy when every failure is a failure to follow an instruction. Match the model to the failure you fear, not to the volume you expect.
Topic binding config.yaml, key telegram.free_response_topics -1004371805465:<N>, quoted A clone carries the topic of the source profile, so two bots answer one message. Telegram builds a thread id from a message id, so the fourth topic does not take the number 4. This group gave the fourth topic the id 157. Read the id from the address bar of Telegram Web.
Routing description profile.yaml, keys description and description_auto "Interactive prompt writing in the Prompts topic. Never a work destination. Do not assign kanban tasks here." Creating a profile makes it assignable at once, and an empty description is no refusal. Write the sentence with profile describe --text, which sets description_auto: false in the same call. Do not use config set, which writes the other file.
Identity and limits SOUL.md Four limits, the Checked trailer, one message with one fenced block, one question for each message A rule the user can edit is a rule the user can delete. Keep the verification rule out of the editable file.
Board membership config.yaml, key kanban.orchestrator_profile crazydave, and no work ever assigned Test the claim with one decompose run on a task worded to invite the mistake. Never assert it.
Skill kit The skills/ directory of the profile ste-writing only, every other directory deleted A clone of a cut profile looks cut. The kit that survived the earlier cut belongs to the earlier role. Read the count, never the appearance. A delete alone does not hold, because skills_sync rebuilds category directories. Write .no-bundled-skills with hermes skills opt-out first.

Why these seven

A profile holds hundreds of settings. Seven of them decide whether a specialist behaves as a specialist. The rest arrive correct from the clone and stay correct.

Three decisions give the agent a place: the bot it speaks through, the topic it listens to, and whether the board may send it work. Three give it a character: the model that runs it, the description the decomposer reads, and the soul file that states its limits.

Miss one of the first three and the agent is unreachable, or it answers in someone else's room. Miss one of the last three and it answers everything, which is the contamination this whole project exists to avoid.

The seventh arrived late, and it arrived from a real reply. A clone carries the skill kit of the profile it copied. Torchwood loaded a skill for kanban workers during an interview, and its soul file forbids every kanban command. Lesson 30 cut the kit and record 0029 holds the reply that exposed it.

No eighth decision holds the working directory. Jokot intends to run this roster on a server, and every machine setting is one more command to repeat there. Torchwood finds a project with one find and records the root in memory instead. Record 0033 holds the two rejected designs.

The order that matters

Knowledge — three rules of sequence
  • Create the bot before the profile. The token replacement is a separate step, because --clone-from copies .env.
  • Read the thread id. Never assume the next number. Torchwood owns thread 157, and it is the fourth topic in the group.
  • Test the routing description with one decompose run. Never assert it.
  • Give a soul file a search, never a path. A path is one more command on the next machine.
