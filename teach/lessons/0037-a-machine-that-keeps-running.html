A background service on Linux needs a decision about scope, and the default scope has a trap that a laptop never shows you

The trap: a user service stops when you log out

Knowledge

Hermes installs its systemd unit in user scope by default. Line 1184 of gateway.py holds the line that chooses:

systemctl_prefix = "systemctl " if system else "systemctl --user "

System scope is the other option. Line 1813 writes the unit to /etc/systemd/system, and line 1829 states that system scope needs root.

User scope avoids root, and it carries one condition. Linux stops a user scope unit when the last session of that user closes. You start four bots over SSH, you close the terminal, and all four stop. The server keeps running, and the roster goes silent.

Linger removes that condition. It keeps a user manager alive with no session open.

Hermes already knows this

Hermes does not wait for you to find the trap. Line 1955 of gateway.py runs the command itself:

["loginctl", "enable-linger", username],

The docstring at line 1922 states the condition. The command works without root when polkit permits it. When polkit denies it, lines 1965, 1987 and 1996 all answer with the same fix: sudo loginctl enable-linger <user>.

So why run it yourself in this lesson? Because the automatic attempt happens during gateway install in Task 3. A denied attempt there stops the install, and you then debug two things at once. Running it now removes that path. The command changes nothing when linger is already on.

Make the user, and keep its services alive

Skill — hands on 
sudo adduser --disabled-password --gecos "" hermes
sudo loginctl enable-linger hermes
loginctl show-user hermes | grep Linger

Expect Linger=yes. That one line is the whole proof. If it reads Linger=no, stop and report, because every later task depends on it.

The account takes no password. You reach it with sudo -u hermes -i from your own account, and rsync reaches it over SSH.

Four profiles become four independent units

Knowledge

get_service_name() at line 1797 builds the unit name from HERMES_HOME. Its own docstring states the rule:

Default ``~/.hermes`` returns ``hermes-gateway`` (backward compatible).
Profile ``~/.hermes/profiles/coder`` returns ``hermes-gateway-coder``.

So this roster becomes four units: hermes-gateway-crazydave, hermes-gateway-peashooter, hermes-gateway-sunflower and hermes-gateway-torchwood.

Four units, not one, is what lets Task 5 start the bots one at a time and stop after the first failure. It is also what lets you restart one bot later while the other three keep answering.

Swap is not a speed setting

Knowledge

Four gateways idle at 181 MB together on the Mac. The measured values are 50.2, 45.1, 43.7 and 42.1 MB. That is 4.5% of 4 GB, and it looks like plenty of room.

Idle is not the number that matters. The gateway runs the agent inside the same process, so memory grows while a bot answers. A language server adds 200 MB to 500 MB while it runs. Four bots doing code work at the same time can reach about 2 GB.

Linux with no swap does not become slow when memory runs out. It stops a process. The kernel picks the process, and it tends to pick the largest one, which here is a bot in the middle of answering.

Skill — hands on 
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h

Expect the Swap: row to read 2.0Gi in the total column. The line added to /etc/fstab is what brings the swap file back after a reboot.

The chmod 600 is not decoration. swapon refuses a swap file that other users can read.

Install the one package the installer asks for by name

Skill — hands on 
sudo apt-get update && sudo apt-get install -y git curl ripgrep
rg --version

Expect a version line. Line 291 of setup-hermes.sh reads sudo apt install -y ripgrep && INSTALLED=true, so the installer asks for this package by name. Install it first and the installer in Task 3 has one less thing to do.

Nothing here installs Python. Line 36 of the installer pins PYTHON_VERSION="3.11", and uv downloads that version itself. The version that Ubuntu ships has no effect.

Prove the server can reach the two hosts that matter

Skill — hands on 
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://api.telegram.org
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://api.anthropic.com

Expect an HTTP code and a time for each host. Both endpoints sit outside Indonesia, and the quality of international transit is the real thing this purchase buys.

This is a stop condition. A time of more than 1 second to either host means you stop and report before Task 3. A slow path here becomes a slow reply from every bot, every time, and no later step repairs it.
