Lesson 36 · Stage 6 build

A copy is not finished when rsync exits. It is finished when two measurements of the same roster agree.

Stage 6 moves four profiles to a server. The payload holds ten SQLite databases, and every one of them carries conversation history that exists in no other place. This lesson builds the script that proves the copy. It runs on the Mac before the move and on the server after it. The two outputs must match. Lesson 35 read one database to find a stopped task. This lesson reads ten to find a lost row.

A number in a document is stale before anybody reads it

Knowledge

The tasks table in kanban.db held 84 rows on 18 September 2026. It held 90 rows on 20 September 2026. Nobody made an error. The bots worked for two days.

So a verification step that compares the server against a count written in a plan fails for the wrong reason. The count was correct when the author wrote it, and the roster moved on.

The rule that follows: compare two measurements of the same roster. Never compare a measurement against a number in a document.

The script prints a count and an integrity result

Skill — hands on

Write this file to hermes-config/scripts/roster-manifest.sh:

#!/usr/bin/env bash
# roster-manifest.sh -- print a count and an integrity result for every
# database that Stage 6 copies. Run on the Mac before the copy, and on the
# server after it. The two outputs must be identical.
#
# Keys are relative to HERMES_HOME, so the output does not name a machine.
set -uo pipefail
H="${HERMES_HOME:-$HOME/.hermes}"

row() {  # row <key> <db> <table>
  if [ -f "$2" ]; then
    printf '%-34s %8s  %s\n' "$1" \
      "$(sqlite3 "$2" "SELECT COUNT(*) FROM $3;" 2>/dev/null || echo ERR)" \
      "$(sqlite3 "$2" 'PRAGMA integrity_check;' 2>/dev/null | head -1)"
  else
    printf '%-34s %8s  %s\n' "$1" absent -
  fi
}

row "kanban/tasks"          "$H/kanban.db" tasks
row "kanban/task_events"    "$H/kanban.db" task_events
row "kanban/task_comments"  "$H/kanban.db" task_comments
row "kanban/task_links"     "$H/kanban.db" task_links
row "kanban/task_runs"      "$H/kanban.db" task_runs
row "root/messages"         "$H/state.db"  messages

for d in "$H"/profiles/*/; do
  p="$(basename "$d")"
  row "$p/messages"  "$d/state.db"    messages
  row "$p/sessions"  "$d/state.db"    sessions
  row "$p/projects"  "$d/projects.db" projects
done

Two details carry the whole design. The keys start at HERMES_HOME, so no row names a machine. The loop reads profiles/*/, so the script finds the profiles instead of listing them.

Run it, and read the eighteen rows

Skill — hands on 
bash hermes-config/scripts/roster-manifest.sh

Expect 18 rows. The last column reads ok on every row except one. The counts on 20 September 2026 were 90 for kanban/tasks, 1059 for root/messages, 721 for crazydave/messages, 1815 for peashooter/messages, 617 for sunflower/messages, and 290 for torchwood/messages.

Your numbers will be larger. The bots kept working. A larger number is correct, and a smaller number is a defect.

The row that reads absent is the important one

Knowledge

One row prints absent and a dash: sunflower/projects. Three profiles hold a 44 KB projects.db, and sunflower holds none.

An earlier version of this loop carried no [ -f ] test. That version did not report the missing file. It created the missing file, because sqlite3 creates an empty database at any path that it cannot find.

So the loop would have manufactured a file that the roster never had, and the copy would have carried the new file to the server. A check that writes is not a check.

Skill — hands on

Prove that the script writes nothing:

ls /Users/jokot/.hermes/profiles/sunflower/projects.db

Expect No such file or directory. Run this after the manifest, never before it. The test is worth nothing in the other order.

The same file must run on both machines

Skill — hands on 
HERMES_HOME=/Users/jokot/.hermes bash hermes-config/scripts/roster-manifest.sh | head -3

Expect the same first three rows. The script reads ${HERMES_HOME:-$HOME/.hermes}, which is the idiom that the upstream installer uses at setup-hermes.sh:402. The server runs this file with no edit.

Then install the live copy and prove that the two files match:

cp hermes-config/scripts/roster-manifest.sh \
   ~/.hermes/profiles/crazydave/scripts/roster-manifest.sh
chmod +x ~/.hermes/profiles/crazydave/scripts/roster-manifest.sh
diff hermes-config/scripts/roster-manifest.sh \
     ~/.hermes/profiles/crazydave/scripts/roster-manifest.sh && echo IDENTICAL

Four gates, and the one that catches a silent failure

Knowledge

The manifest feeds four gates. Each gate names what stops the work.

  1. Gate A runs after the copy and before any bot starts. Both machines print a manifest, and diff compares them. They must be identical.
  2. Gate B runs for each bot before the next bot starts. The bot must reply, and the reply must show its own history.
  3. Gate C runs after the last bot answers. The roster audit must stay silent, and every count must be equal or larger.
  4. Gate D runs one week later. Four memory peaks must add to less than 2.5 GB.

Gate A compares files. Gate B compares behavior, and that difference is the point. A gateway can report running, reply in Telegram, and still hold no history, because it opened a database in a place the copy never touched. The file test passes and the bot is empty. So Gate B asks the bot about its own recent work.

Why integrity_check belongs here

PRAGMA integrity_check answers ok on all ten databases today. A copy taken while a write-ahead log stays hot can land corrupt, and it lands without an error message.

A count alone cannot find that fault. A corrupt page can hold the right number of rows. The manifest prints both values on every row for this reason.

Why does the manifest compare two live runs instead of the counts written in the plan?

Right. The tasks table moved from 84 rows to 90 rows in two days. Any number written in a document is stale.

Wrong. A document holds any number correctly. The roster changes the number after the author writes it.

Wrong. COUNT(*) reads a copied database correctly. The problem is the reference value, not the query.

Why does every database path carry a [ -f ] test?

Right. Without the test the loop manufactures sunflower/projects.db, and the copy then carries a file the roster never had.

Wrong. sqlite3 reports success, because it made the file that it could not find.

Wrong. Sidecar files matter for a read-only connection, which Lesson 35 covers. They are not the reason for this test.

What does Gate B prove that Gate A cannot?

Right. Gate A proves that the files match. A gateway can still open a database somewhere else and answer with no history.

Wrong. Gate A already proves that, because it compares a row count on both machines.

Wrong. Linger and the unit files carry that property. No gate in Stage 6 tests a reboot.

Checkpoint

Primary source: The SQLite documentation on PRAGMA integrity_check states what the check reads and what it cannot find. Read it beside the write-ahead log page, which explains why a copy taken from a live database needs a checkpoint first.
