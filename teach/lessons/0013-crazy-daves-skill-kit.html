Lesson 13 of the Stage 2 build

Pruning almost everything, not most things

Lesson 9 pruned Peashooter and Sunflower down to what their domains actually need — each kept a real working set. Crazy Dave's domain line reads "none," so this cleanup goes the other direction: almost nothing survives.

Why this cleanup looks different

Knowledge

Crazy Dave was created with --clone-from default in Lesson 12, same as every other profile — so it inherited the same full, unpruned bundle Peashooter and Sunflower started with before Lesson 9. Running hermes skills list -p crazydave --enabled-only confirms it: the entire default bundle, still there.

The difference is what Crazy Dave's own SOUL.md says it's allowed to do: "Domain: none — you do not answer requests yourself." Peashooter's and Sunflower's cleanups were case-by-case — each bundled skill got checked against a real domain line, and a lot of them fit. Crazy Dave's domain line rules out the entire bundle at once. There's no case-by-case review to do, because there's no domain for a skill to fit into.

The one exception

Knowledge

One bundled skill does fit: devops/kanban-orchestrator. Its own description calls it "the deeper playbook when you're an orchestrator profile whose whole job is routing" — and Lesson 15 sets kanban.orchestrator_profile to 'crazydave' in every profile's config.yaml, naming Crazy Dave as that orchestrator explicitly.

devops/kanban-worker — the skill Peashooter and Sunflower both kept in Lesson 9 — is the mirror-image case: it documents pitfalls for a profile the dispatcher spawns to actually do a task. Crazy Dave is never dispatched that way, so it goes.

Worth knowing, not a contradiction

kanban-orchestrator's playbook describes a fuller job than Crazy Dave's current SOUL.md asks for — it covers discovering profiles and fanning a task out across several with explicit assignee= reasoning. Crazy Dave's own hard rule is narrower: create one task, no assignee logic, stop. The skill stays anyway. Its core "don't do the work yourself" rule reinforces Crazy Dave's hard rule rather than fighting it, and if Lesson 16's end-to-end test shows Crazy Dave actually needs the fuller playbook, it's already in place. If it turns out unused, that costs nothing.

Do this now

Skill — hands on

Delete everything except the orchestrator skill:

cd ~/.hermes/profiles/crazydave/skills

# Whole categories — nothing inside them fits a profile with no domain
rm -rf apple autonomous-ai-agents computer-use creative data-science \
       dogfood email github hermes-desktop-plugins media mlops \
       note-taking openclaw-imports productivity research smart-home \
       social-media software-development yuanbao

# Mixed category — remove the worker half, keep the orchestrator half
rm -rf devops/kanban-worker

Verify:

hermes skills list -p crazydave --enabled-only

This should report zero enabled skills. That's correct, not a bug — the one skill left, devops/kanban-orchestrator, declares environments: [kanban], so it stays hidden until Lesson 15 activates the kanban environment, the same way kanban-worker stayed hidden for Peashooter and Sunflower after their own Lesson 9 cleanup.

Why does Crazy Dave keep devops/kanban-orchestrator but not devops/kanban-worker, the opposite of what Peashooter and Sunflower kept?

Right — kanban-worker documents pitfalls for a profile spawned to do a task; Crazy Dave never does the task itself, so it never hits those pitfalls.

Not the case — Crazy Dave inherited the full default bundle at creation, kanban-worker included, same as Peashooter and Sunflower did before their own cleanup.

Not a real constraint — Peashooter and Sunflower both have kanban-worker enabled at the same time as this cleanup runs.
