Lesson 15 of the Stage 2 build

One board, three profiles

Every profile in this project has existed on its own so far — a separate memory, a separate skill kit, a separate bot. This lesson gives all three a shared surface: one task board Crazy Dave writes to and Peashooter and Sunflower work from.

What the board actually is

Knowledge

The kanban board is a single SQLite file, shared across every Hermes profile on this machine — not one board per profile. A task moves through five columns: triage → todo → ready → running → done. Crazy Dave's SOUL.md hard rule from Lesson 12 creates a task and stops; everything after that — deciding who works it, actually running it, marking it done — is the board's job, not Crazy Dave's.

hermes kanban decompose is the step that turns a raw task into assigned work: it reads every profile's profile description (the routing signal from Lesson 10) and fans the task into one or more children, each with an explicit assignee=. A dispatcher — running inside hermes gateway start, not a separate process — claims ready tasks and spawns the assigned profile as an isolated worker to actually do the work.

Naming the orchestrator

Knowledge

Every profile's config.yaml already has a kanban: section — it was there before this lesson, empty and unused. One key in it matters now: orchestrator_profile, currently '' in all three profiles. This lesson sets it to 'crazydave' in all three, not just Crazy Dave's own file — any profile's gateway might run the dispatch pass, so each one needs to know who the designated orchestrator is.

This is the same lock you saw fire in Crazy Dave's log a moment ago: "another gateway already holds the dispatcher lock". Only one running gateway actually dispatches at a time, no matter how many are up — the lock file at ~/.hermes/kanban/.dispatcher.lock enforces that. Setting orchestrator_profile doesn't change who holds the lock; it tells decompose which profile's requests to treat as routing instructions rather than direct work.

Do this now

Skill — hands on

1. Create the board:

hermes kanban init
hermes kanban boards

init is idempotent — safe to run even if a board already exists. boards should list one board.

2. Set the orchestrator in all three profiles. For each of peashooter, sunflower, and crazydave, open ~/.hermes/profiles/<name>/config.yaml, find the kanban: section, and change:

kanban:
  orchestrator_profile: ''

to:

kanban:
  orchestrator_profile: 'crazydave'

Leave every other key in that section — dispatch_in_gateway, failure_limit, and the rest — exactly as it is.

3. Restart all three gateways so the new config loads:

hermes gateway restart -p peashooter
hermes gateway restart -p sunflower
hermes gateway restart -p crazydave
hermes gateway status

4. Mirror the three config files into this repo (no live secret lives in config.yaml — the model API key is stored separately by hermes auth):

cp ~/.hermes/profiles/peashooter/config.yaml hermes-config/peashooter/config.yaml
cp ~/.hermes/profiles/sunflower/config.yaml hermes-config/sunflower/config.yaml
mkdir -p hermes-config/crazydave
cp ~/.hermes/profiles/crazydave/config.yaml hermes-config/crazydave/config.yaml
cp ~/.hermes/profiles/crazydave/SOUL.md hermes-config/crazydave/SOUL.md

5. Commit:

git add teach/lessons/0015-the-shared-kanban-board.html \
        teach/reference/glossary.html \
        hermes-config/peashooter/config.yaml \
        hermes-config/sunflower/config.yaml \
        hermes-config/crazydave/config.yaml \
        hermes-config/crazydave/SOUL.md
git commit -m "Add Lesson 15: initialize shared kanban board"

Why does orchestrator_profile get set to 'crazydave' in Peashooter's and Sunflower's config.yaml too, not only Crazy Dave's?

Right — the dispatcher lock is held by whichever gateway gets there first, not always Crazy Dave's, so the setting has to travel with every profile.

Not their job — Lesson 9 kept them on kanban-worker, the skill for a profile a task gets dispatched to, not one that files tasks.

Not a technical requirement — init only creates the shared database file, unrelated to any profile's config.
