Lesson 19 of the Stage 3 build

The gate that decides who answers

Three bots now sit in one room. Left alone they will all answer every message, or none of them will. This lesson picks the one setting that gives each bot a home topic without locking it out of the others — and shows why the obvious setting is the wrong one.

Read the gate in order

Knowledge

When a group message arrives, Hermes's Telegram adapter runs one function to decide whether this profile should respond. The checks run in a fixed order, and the first one that matches wins:

allowed_chats        → outside the list? stop
guest mention        → respond
free_response_chats  → respond
free_response_topics → respond
require_mention      → not required? respond
reply to the bot     → respond
mention of the bot   → respond
mention_patterns     → respond if matched

Read the fourth and fifth lines together. free_response_topics is checked before require_mention. That is the whole trick: a topic on that list answers plain messages, and every other topic still requires a mention. One setting produces both halves of the behavior you want.

The list is a set of strings of the form <chat_id>:<thread_id> (_telegram_free_response_topics, plugins/platforms/telegram/adapter.py:7251). Those are the numbers you wrote down in Lesson 18.

Correction — the obvious setting is a trap

The first draft of this design used ignored_threads: give each bot the list of topics it should ignore, and let mentions still reach it. That is wrong, and the documentation says so directly. An ignored topic is skipped "before the mention and free-response checks run", and "even when the group would otherwise allow free responses or mention-triggered replies."

So ignored_threads is absolute. A bot that ignores #Planning cannot be summoned into #Planning by any means. That deletes the half of the reference design where you can call any specialist into any conversation — the reason for having one room instead of three.

The error was caught by reading the sentence past the part that agreed with the plan. Use no ignored_threads entry anywhere in this stage.

A key with no documentation

free_response_topics appears nowhere in Hermes's Telegram documentation. It exists only in the adapter source. Its sibling free_response_chats opens a whole chat and is documented, which is probably why the undocumented one is easy to miss.

Undocumented is not the same as unsupported, but it is worth knowing what you are standing on. The behavior in this lesson was confirmed by reading the gate function, not by trusting a document. If a future Hermes version changes it, the symptom will be every bot answering at once, and the fix will be in the same function.

Do this now

Skill — hands on

1. Find the block you are editing. Each profile's config.yaml already has a top-level telegram: block, and today it holds two keys:

grep -A3 '^telegram:' ~/.hermes/profiles/peashooter/config.yaml
telegram:
  reactions: false
  allowed_chats: ''

2. Add four lines to each of the three files. Substitute your own chat id, and each profile's own thread id. Peashooter takes #Coding:

telegram:
  reactions: false
  allowed_chats: ''
  require_mention: true
  exclusive_bot_mentions: true
  free_response_topics:
    - "-1001234567890:3"

Sunflower takes #Planning, and Crazy Dave takes General, which is thread 1. Nothing else differs between the three files.

Two rules about that value. Quote it. A bare -1001234567890:3 starts with a minus sign and contains a colon, which is ambiguous in YAML. Leave allowed_chats empty. A non-empty allowed_chats becomes a second gate, checked first, that the group would also have to pass.

3. Restart the three gateways. A running gateway holds its configuration in memory:

for p in peashooter sunflower crazydave; do hermes gateway restart -p $p; done
hermes gateway status

4. Run five tests, in this order. Each one isolates a different check in the gate:

  • Post hello in #Coding with no mention. Only Peashooter should answer. This tests free_response_topics.
  • Post @your_sunflower_bot hello in #Coding. Only Sunflower should answer. This tests exclusive_bot_mentions.
  • Post hello in #Planning. Only Sunflower should answer, and Peashooter must stay silent. This tests require_mention.
  • Post hello in #General with no mention. Only Crazy Dave should answer, which tests the third free_response_topics entry. Then run hermes kanban list. Expect a new task whose body is the word hello. That task is a defect, not a success. Leave it on the board and read Lesson 20, which explains the cause and archives it.
  • Send a private message to each of the three bots. Each should answer exactly as it did before this lesson. This is the regression check.
If a test fails, read before guessing

Two failures look alike from the chat window and are told apart by one command each.

grep -A8 '^telegram:' ~/.hermes/profiles/peashooter/config.yaml
hermes gateway logs -p peashooter --lines 100

Nobody answers an unnamed message, and the configuration is correct. That is BotFather group privacy, from Lesson 18. Telegram never delivered the message, so the log has no entry for it. An empty log is the evidence.

Every bot answers one unnamed message. Then require_mention is not reaching the adapter. The first command shows whether the key is really in the file and really under telegram:, rather than indented into a neighbouring block.

Why does this design use free_response_topics instead of ignored_threads?

Right. ignored_threads is absolute — it is applied ahead of both the free-response and the mention checks, so a bot ignoring a topic cannot be summoned there at all.

True of a denylist in general, and a real cost, but not the reason. The reason is that it also blocks mentions.

It is fully supported and implemented at adapter.py:7331. It works exactly as documented — the documented behavior is what makes it wrong here.

Checkpoint

Primary source: the gate function itself, in ~/.hermes/hermes-agent/plugins/platforms/telegram/adapter.py. Search for _telegram_free_response_topics and read the function that calls it. Hermes's Telegram guide covers the documented neighbours of these keys, and is the better read for exclusive_bot_mentions.
