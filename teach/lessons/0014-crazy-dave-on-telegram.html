Lesson 14 of the Stage 2 build

A third door, same mechanism

Peashooter and Sunflower each got a Telegram bot in Lessons 5 and 11. Crazy Dave gets its own third bot now — same gateway, same two setup paths, its own separate chat.

What's already known

Knowledge

Nothing new about the mechanism itself — see the Gateway glossary entry. What matters, same as Lesson 11: hermes gateway setup attaches to whichever profile is active, so hermes profile use crazydave has to run first. Get that wrong and the new bot ends up wired to the wrong SOUL.md — in this case, a bot that should only create kanban tasks would instead answer directly as whichever profile was actually active.

Known failure mode — don't re-debug it

Same note as Lesson 11: Automatic setup failed once already in Telegram Web, documented in learning record 0006. If it fails the same way a third time, skip straight to Manual BotFather.

Do this now

Skill — hands on

1. Make Crazy Dave the active profile, then run setup:

hermes profile use crazydave
hermes gateway setup

Pick Telegram. Try Automatic ([1]) first. If it errors with no response, switch to Manual: message @BotFather, run /newbot, pick a name and a globally-unique ...bot-suffixed username — different from both Peashooter's and Sunflower's — and paste the returned token into the manual prompt.

2. Install it as a standing background service:

hermes gateway install

3. Confirm it's running:

hermes gateway status

Should show all three gateways running now — Peashooter, Sunflower, and Crazy Dave, each a separate bot, each talking to its own profile.

If you message Crazy Dave's new bot and it answers your question directly instead of just confirming a task was created, what's the most likely place to look first?

Right — either the bot got wired to the wrong profile at setup, or this is Crazy Dave's own version of Peashooter's Lesson 3 prompt-dilution bug.

Not the first thing to check — a working reply from the bot at all means Telegram's side is fine.

Unrelated to this symptom — an uninitialized board would make the kanban tool call fail, not make Crazy Dave answer directly instead of calling it.
