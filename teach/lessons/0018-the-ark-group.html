Lesson 18 of the Stage 3 build

One room, three doors

Stage 2 ends with three bots in three separate private chats. A question that touches two domains has no single place to live. The reference project solves this with one room, divided into topics, one topic per specialist. This lesson builds the room. Lesson 19 makes the bots behave inside it.

What a topic actually is

Knowledge

A Telegram forum topic is a named sub-thread inside a supergroup. Telegram gives each topic a numeric message_thread_id, and every message carries the id of the topic it was posted in. That number is the whole routing mechanism you will use in Lesson 19.

Two facts about the numbering matter, and both come from Hermes's own Telegram adapter rather than from the Telegram interface. Telegram omits message_thread_id for the General topic, and Hermes normalizes that absence to thread 1 (_GENERAL_TOPIC_THREAD_ID = "1", plugins/platforms/telegram/adapter.py:583). Topics you create yourself get their own numbers, and those numbers are not shown anywhere in the Telegram mobile or desktop app.

This is the layout the reference project uses. Zain Fathoni's The Ark is one group with a topic per specialist, not a folder of private chats. Named back in Lesson 1, adopted now.

The setting that fails silently

Knowledge

Every Telegram bot has a group privacy setting, and it is enabled by default. A bot with privacy enabled receives only group messages that name it, reply to it, or begin with a slash command. Every other message never reaches the bot at all.

That is fatal for the design in Lesson 19, where each bot must answer plain messages in its own topic. It is also the hardest failure to diagnose, because nothing reports an error. Telegram simply does not deliver the message, so Hermes has nothing to log and the bot has nothing to ignore. You see silence, and silence looks identical to a configuration mistake.

Disable it now, before you write any configuration. Then you can read a later silence as a real signal.

Do this now

Skill — hands on

1. Create the group and enable topics. In the Telegram app:

  • Create a new group. Name it something you will recognize in a list — Ark works.
  • Add all three bots: Peashooter, Sunflower, Crazy Dave.
  • Open group settings, then Edit, then enable Topics. Telegram converts the group to a supergroup at this point, and its chat id changes to one beginning -100.
  • Create two topics: Coding and Planning. Do not create General — it already exists.
  • Promote each of the three bots to administrator. A non-administrator bot in a supergroup can miss messages that Telegram delivers only to administrators.

2. Disable group privacy for all three bots. Open a chat with @BotFather and, for each bot in turn:

/mybots
  → choose the bot
  → Bot Settings
  → Group Privacy
  → Turn off

Then remove each bot from the group and add it again. Telegram can keep the earlier delivery behavior for a bot that is already a member when the setting changes.

3. Read the four identifiers. The chat id and the thread ids are not visible in the mobile or desktop app. Telegram Web puts both in the address bar:

  • Open web.telegram.org/a/ and open the group.
  • Open the Coding topic. The address ends #-1001234567890_3. The first number is the chat id, the second is the thread id.
  • Repeat for Planning.
  • General shows no trailing number. Its thread id is 1.

Write all four numbers down. Lesson 19 puts them into three configuration files, and a wrong digit produces exactly the same symptom as a bot that never answers.

4. Sanity-check what you wrote. The chat id starts with -100. The three thread ids are all different. General is 1. If any of those three checks fails, read the address bar again rather than guessing the value.

Nothing here breaks your direct messages

This lesson adds a room. It removes nothing. Each bot keeps its own gateway, its own token, and its own private chat with you, exactly as Stage 1 and Stage 2 left them. Lesson 19's settings apply to group chats only — require_mention is checked on a group message path that a private chat never enters.

That property is why this stage uses three gateways rather than Hermes's profile_routes multiplexing. Multiplexing would replace three working gateways with one untested configuration and put the private chats at risk, to save nothing you need.

You disable group privacy on all three bots. What does that setting control?

Right. It is a delivery filter on Telegram's side, above Hermes. With it enabled, a bot never receives the message, so no Hermes setting can make it answer and no Hermes log records anything.

That is administrator rights, a separate setting. Both matter here, but privacy is the one that governs message delivery.

Storage is a Hermes concern, decided by the profile. Group privacy is a Telegram setting applied before Hermes sees anything.
