Lesson 7 of the Stage 2 build

A second brain, a second bot

Peashooter proved the pattern works. Stage 2 repeats it on purpose — a second specialist, in a domain Peashooter should never touch, so scope stays split instead of drifting back into one assistant doing everything.

What Sunflower is

Knowledge Sunflower is Stage 2's second specialist. Its domain is brainstorming, planning, task breakdown, and writing PRDs, proposals, and specs — turning a rough idea into a structured document. It does not write or review code; that stays Peashooter's job. The name follows the same logic as Peashooter's: in Plants vs. Zombies, Sunflower produces the sun every other plant spends to act. Here, Sunflower produces the plans Peashooter later implements.

This is the same fix as Stage 1, applied a second time: instead of widening Peashooter's scope to also cover planning, a second, separate profile keeps the two domains from bleeding into each other — the "context contamination" problem from Zain Fathoni's original writeup, the same source Stage 1 started from.

Do this now

Skill — hands on

1. Create the profile, with a description from the start (not added later, the way Peashooter's was refined mid-project):

hermes profile create sunflower --clone-from default --description "Brainstorming, planning, task breakdown, and writing PRDs, proposals, and specs"

2. Make it the active profile, then reset its memory immediately — before it is ever used for real:

hermes profile use sunflower
echo yes | hermes memory reset
Correction — why reset memory before first use, not after

In Stage 1, Peashooter's memory turned out to hold unrelated content from the default profile, discovered only while preparing Lesson 4 — see learning record 0005. The cause: --clone-from copies memory files along with config, not just config. Sunflower gets the fix applied from the start this time, instead of being found as a bug later.

3. Confirm the reset actually worked:

cat ~/.hermes/profiles/sunflower/memories/MEMORY.md

This should print No such file or directory — a clean slate. The file gets created automatically the first time Sunflower writes to it.

4. Assign a model. While sunflower is still the active profile:

hermes model

Pick the same OpenRouter model used for Peashooter, unless you want to try a different one for this specialist.

Why does Sunflower get its own profile instead of a new mode inside Peashooter?

Right — a mode inside Peashooter would mix planning context into the same memory and system prompt as coding, the exact contamination this project is built to avoid.

Not the reason — this is about keeping domains isolated, not about speed.

Telegram doesn't enforce this — the one-bot-per-profile design is a choice this project made, not a platform requirement.
