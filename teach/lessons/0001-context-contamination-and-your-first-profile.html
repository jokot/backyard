Lesson 1 of the Peashooter build

Context contamination, and your first specialist

Why a "personal AI army" is more than a gimmick, and the first real piece of yours: a Hermes profile named Peashooter.

The problem, in Zain Fathoni's words

The project you're modeling this on is Zain Fathoni's "Project Transformers: Building a Personal AI Army" — read it in full when you have 10 minutes; it's the primary source for everything in this lesson. Here's the problem he ran into using one general-purpose AI assistant for everything:

tax questions contaminated code reviews

That's context contamination: one assistant, many unrelated domains, and the context from one bleeds into another. Ask it about your taxes, then ask it to review a pull request, and it's a worse reviewer than it would have been fresh — because it's still carrying tax-shaped context it doesn't need and you didn't want mixed in.

His fix mirrors how organizations already solve this: "We specialize. We have teams. Each person owns a domain." Instead of one assistant, he built several — each with a narrow domain, its own memory, and no visibility into the others' conversations.

Knowledge The general term for "several AI agents coordinating on work instead of one doing everything" is a multi-agent system. Zain's version has a coordinator agent ("Optimus") that routes requests to specialist agents ("Wheeljack" for code, "Prowl" for life admin, and so on). We are not building the coordinator yet — that's Stage 2. Today we build one specialist, standing alone, and prove it stays in its lane.

Our mechanism: a Hermes profile

Zain's framework (OpenClaw) gives each agent its own process and memory. Hermes Agent — what we're building on — gives you the same isolation through something called a profile. One profile = one agent identity. Different profiles don't see each other's memory or conversation history. That's the whole mechanism behind avoiding context contamination: separate profile, separate context, by construction — not by asking the model nicely to forget.

Today's specialist is Peashooter — named for the first, simplest plant you ever place in Plants vs. Zombies, matching its role as the first specialist in this project. Its domain: coding and engineering, nothing else.

Do this now

Skill — hands on

In your terminal, run:

hermes profile create peashooter --clone-from default --description "Coding and engineering specialist"

--clone-from default copies your existing model config, skills, and tools into the new profile, so Peashooter isn't starting from nothing. The --description isn't read by anything yet — but it will be, the moment Stage 2 adds a router that needs to decide which profile handles which task. Write it well now.

Confirm it worked:

hermes profile list

You should see both default and peashooter listed.
