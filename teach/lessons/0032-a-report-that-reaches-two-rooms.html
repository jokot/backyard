Lesson 32 of the Stage 5 build

A worker finds its root task through children, not parents

Crazy Dave writes one Fizzy comment, and writes it only at root task completion. A blocked task never reaches root task completion, so no comment reaches its card. On 14 September 2026 two tasks blocked, and the Fizzy card of each root task showed neither message.

The report that never reached the card

Knowledge

Record 0043 lists two tasks that blocked on 14 September 2026, read from the task_events table:

676  t_8e9c7cfb  blocked  17:28:35  review-required: index.html + style.css built
681  t_34115dfd  blocked  17:32:38  review-required: Connect Four logic ... needs_input

Neither task reached done that day. Crazy Dave reads a fizzy:<number> comment only on root task completion, so it never ran that read for either task. The Fizzy card of each root task showed neither message.

This lesson builds one command, hermes-report.sh, that a worker calls to report a message right away. Telegram receives every message. Fizzy receives the same message too, when a card exists, so a blocked task still reaches a room.

Children point backward

Knowledge

Every task on the board carries two lists, parents and children. The two words read like a family tree, and the reading runs backward for this board. A real query against a root task and one of its workers shows the direction:

t_e6f5dc9f  root    parents: 5 worker ids       children: 0
t_29e6cbb8  worker  parents: ['t_3ce59841']     children: [..., 't_e6f5dc9f']

State the rule in one sentence. A parent must reach done first, and a child waits. This is a dependency edge, and the root task waits on every one of its workers, so the root task lists its workers as parents, never as children.

State the consequence. A worker reaches its root task through children, never through parents. The worker task t_29e6cbb8 above carries its own root id, t_e6f5dc9f, inside its children list, not inside its parents list.

Do this now — write the script

Skill — hands on

Write this file at ~/.hermes/scripts/hermes-report.sh. Copy every line, including every comment:

#!/usr/bin/env bash
# Report one message to Telegram, and to the Fizzy card when a card exists.
#
# A worker calls this script instead of `hermes send --to telegram`.
# Telegram always receives the message. Fizzy receives a comment only when
# the task chain carries a `fizzy:<number>` comment.

set -uo pipefail

MSG="${1:-}"
if [ -z "$MSG" ]; then
  echo "usage: hermes-report.sh \"<the message>\"" >&2
  exit 2
fi

# Telegram first. This send is the report that Jokot reads, so a Fizzy
# defect never costs a report.
if ! hermes send --to telegram "$MSG" >/dev/null 2>&1; then
  echo "report: telegram send failed" >&2
  exit 1
fi

TASK="${HERMES_KANBAN_TASK:-}"
[ -z "$TASK" ] && exit 0

# Print the card number held in a `fizzy:<number>` comment, or print
# nothing. The quotation marks anchor the match, so a comment that only
# mentions the word fizzy never matches.
card_of() {
  hermes kanban show "$1" --json 2>/dev/null \
    | grep -o '"fizzy:[0-9][0-9]*"' | head -1 | tr -d '"' | cut -d: -f2
}

CARD="$(card_of "$TASK")"

# A dispatched worker owns a child task, and the card belongs to the root
# task. In this board `children` means "waits for me", so the root task
# appears in the children list of the worker task. Probe every task id
# that the worker task mentions. Only a root task carries a fizzy comment.
if [ -z "$CARD" ]; then
  for id in $(hermes kanban show "$TASK" --json 2>/dev/null \
                | grep -o 't_[0-9a-f]\{8\}' | sort -u); do
    [ "$id" = "$TASK" ] && continue
    CARD="$(card_of "$id")"
    [ -n "$CARD" ] && break
  done
fi

if [ -z "$CARD" ]; then
  echo "report: no fizzy card for $TASK" >&2
  exit 0
fi

if ! fizzy comment create --profile crazydave --card "$CARD" \
       --body "$MSG" >/dev/null 2>&1; then
  echo "report: fizzy comment failed for card $CARD" >&2
fi
exit 0

Three rules the script obeys

Knowledge
  • Telegram runs first, because that send is the report Jokot reads.
  • A Fizzy failure never changes the exit code, so a Fizzy defect never reads as a task failure.
  • An absent HERMES_KANBAN_TASK means the caller is not a dispatched worker, so the script stops right after Telegram.

Install and test

Skill — hands on

Read the output on your own machine. Do not trust the exit codes in this lesson until you see them yourself.

Step 1. Install the file and make it executable.

# Write the file with a text editor, then:
chmod +x ~/.hermes/scripts/hermes-report.sh

Step 2. Test the Telegram half with no card.

unset HERMES_KANBAN_TASK
~/.hermes/scripts/hermes-report.sh "stage 5 test one, telegram only"
echo "exit=$?"

Expect one message in the group, and exit=0.

Step 3. Test the empty argument.

~/.hermes/scripts/hermes-report.sh; echo "exit=$?"

Expect the usage line on standard error, and exit=2.

Step 4. Test the card lookup against a finished job. Use the worker task t_8e9c7cfb, which belongs to root task t_7e862706 and card 17.

HERMES_KANBAN_TASK=t_8e9c7cfb \
  ~/.hermes/scripts/hermes-report.sh "stage 5 test three, card lookup"

Expect one Telegram message, and one new comment on Fizzy card 17.

If that task is archived by the time you run this lesson, this query lists every root task that carries a card, and the worker task of each:

sqlite3 ~/.hermes/kanban.db "
SELECT c.body, l.parent_id AS worker
FROM task_comments c JOIN task_links l ON l.child_id = c.task_id
WHERE c.body LIKE 'fizzy:%';"

A worker task lists parents: ['t_3ce59841'] and children: [..., 't_e6f5dc9f']. Which list holds the id of its own root task?

Right. The worker waits for nothing ahead of it, but the root task waits for the worker, so the root id sits inside children.

A parent must reach done before this task starts. The root task starts only after the worker finishes, so it cannot be a parent.

The children list already carries it, at the position shown as t_e6f5dc9f.

fizzy comment create fails for a card. What does hermes-report.sh do next?

Right. The second rule holds: a Fizzy failure never changes the exit code.

Only a failed Telegram send returns exit 1. A Fizzy failure never reaches that branch.

The script has no retry. It prints one line to standard error and exits 0.
