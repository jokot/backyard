The report script cannot see a worker that never speaks

Knowledge

hermes-report.sh, from Lesson 32, runs only when a worker calls it. A worker that stops before it reports sends no message at all, and the task stays blocked in silence.

Record 0043 named two tasks that blocked on 14 September 2026, t_8e9c7cfb and t_34115dfd. The kanban board held both blocked states correctly the whole time. Only a reader was missing.

The SQLite precedence trap

Knowledge

The wrong expression divides a string by a string:

SELECT 'blocked ' || (1000 - 400)/60 || 'm';
-- returns 0

In SQLite, the || operator binds tighter than - and /. The expression above computes 'blocked ' || (1000 - 400) first, then divides that string by 60, then concatenates 'm'. Parentheses around the arithmetic fix the order:

SELECT 'blocked ' || ((1000 - 400)/60) || 'm';
-- returns blocked 10m

The script in full

Skill — hands on

Write this file at ~/.hermes/profiles/crazydave/scripts/blocked-watch.sh. Copy every line, including every comment:

#!/usr/bin/env bash
# Print one line for each kanban task that stayed blocked for more than 60
# minutes. Print nothing otherwise, so a healthy run delivers no message.
#
# The script opens kanban.db without `-readonly`. A read-only connection to
# a WAL database fails when the -shm and -wal sidecar files are absent, and
# those files exist only while a writer holds the database open. This query
# is a SELECT and changes nothing.
set -uo pipefail
DB="${HERMES_KANBAN_DB:-$HOME/.hermes/kanban.db}"
[ -f "$DB" ] || exit 0
sqlite3 "$DB" <<'SQL' 2>/dev/null
SELECT 'blocked ' || ((strftime('%s','now') - e.created_at)/60) || 'm: '
       || t.id || ' (' || COALESCE(t.assignee,'unassigned') || ') '
       || substr(COALESCE(json_extract(e.payload,'$.reason'),''),1,120)
FROM tasks t
JOIN task_events e ON e.task_id = t.id AND e.kind = 'blocked'
WHERE t.status = 'blocked'
  AND e.created_at = (SELECT MAX(created_at) FROM task_events
                      WHERE task_id = t.id AND kind = 'blocked')
  AND e.created_at < strftime('%s','now') - 3600;
SQL
exit 0

Make the file executable:

chmod +x ~/.hermes/profiles/crazydave/scripts/blocked-watch.sh

Prove the formatting

Skill — hands on

A healthy board prints nothing, which proves little. Relax both filters inside a copy, and run that copy instead of the real file:

sed -e "s/t.status = 'blocked'/1=1/" \
    -e "s/e.created_at < strftime('%s','now') - 3600/1=1/" \
    ~/.hermes/profiles/crazydave/scripts/blocked-watch.sh \
    > /tmp/blocked-watch-relaxed.sh
bash /tmp/blocked-watch-relaxed.sh

Expect six lines, one for each historical block. Each line starts with blocked <minutes>m:. Two lines name t_8e9c7cfb and t_34115dfd, the two tasks of record 0043.

The autosubscribe repair

Skill — hands on

Line 14 of kanban-autosubscribe.sh defaults to the private chat. No profile sets HERMES_TELEGRAM_CHAT_ID, so that default fires every time. Replace the line with this default instead:

CHAT_ID="${HERMES_TELEGRAM_CHAT_ID:--1004371805465}"

Read the two dashes with care. The first dash pairs with the colon to form the :- default operator. The second dash is the sign of the negative group id, the value record 0043 established.

Move the file cron can reach

This step moves a real file

kanban-autosubscribe.sh sits in ~/.hermes/scripts/, the one directory a cron job never reads. Lesson 34 already named the rule: a cron job resolves --script only under $HERMES_HOME/scripts. Lesson 17 removed the profile copy of this file, and that removal left the file in the one place a cron job never reads.

Move the file into the profile scripts folder:

mv ~/.hermes/scripts/kanban-autosubscribe.sh \
   ~/.hermes/profiles/crazydave/scripts/kanban-autosubscribe.sh
ls -l ~/.hermes/profiles/crazydave/scripts/

Expect three files, each with mode -rwxr-xr-x.

Create the two cron jobs

Skill — hands on 
hermes -p crazydave cron create 'every 1h' \
  --name blocked-watch --script blocked-watch.sh --no-agent --deliver telegram

hermes -p crazydave cron create 'every 15m' \
  --name kanban-autosubscribe --script kanban-autosubscribe.sh \
  --no-agent --deliver telegram

Both commands pass a bare filename, per the rule Lesson 34 already taught. Each filename resolves under $HERMES_HOME/scripts, which hermes -p crazydave sets to ~/.hermes/profiles/crazydave/scripts.
