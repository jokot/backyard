Lesson 33 of the Stage 5 build

A soul file states one command, and the script holds the steps

Three soul files call hermes send --to telegram on their own, and skip the new report script from Lesson 32. Fizzy never receives a comment when that call runs alone, because only the report script resolves a card. This lesson replaces four lines and removes one, across three files, and adds the delivery step that lets a live chat see the change.

The rule that record 0017 forced

Knowledge

Record 0017 found the same reporting rule written in three separate regions of one SOUL.md. Every region was correct alone. The first edit was not enough, because two other regions still offered a competing procedure. The fix needed two more edits of SOUL.md before one region held the whole procedure.

This lesson follows the same rule. A soul file states one command, and a script holds the steps. The report script from Lesson 32 already holds every step, so each soul file only needs the call.

An edit reaches no open chat by itself

Skill — hands on

A soul file edit does not reach an open chat session by itself. Record 0045 found that the file was correct within one minute, but the running session still used the old prompt until /new. The gateway builds a system prompt once, then stores it for every later turn. Only a fresh session reads the file again.

Send /new inside each topic below. Then send one ordinary message. Wait for the reply before you move to the next profile.

  • #Planning for Sunflower
  • #General for Crazy Dave

Sunflower holds four open Telegram sessions from 9 and 10 September 2026. One of those four sessions serves #Planning today. Without /new, the Sunflower edit reaches nobody in that topic.

Prove the files, then prove the sessions

Skill — hands on

Two commands prove the edit landed, one for the files and one for the live sessions. The file proof is success criterion 4 of the spec.

grep -c 'hermes send --to telegram' ~/.hermes/profiles/*/SOUL.md

It prints one <path>:<count> line for each of the four profiles. Every count must read 0 after your edit. Torchwood already reads 0 today, because that file holds no such line.

The file proof shows the rule on disk. This second command shows the rule inside a live chat.

for p in peashooter sunflower crazydave; do
  printf '%-11s ' "$p"
  sqlite3 -readonly ~/.hermes/profiles/$p/state.db \
    "SELECT COUNT(*) FROM sessions WHERE source='telegram' AND ended_at IS NULL
       AND system_prompt LIKE '%hermes-report.sh%';"
done

A count of 1 or more means the new rule is live for that profile. A count of 0 means either the chat still runs the old prompt, or nobody sent a message after /new. Read the system_prompt column to separate the two cases, because /new leaves it NULL until the first turn.
