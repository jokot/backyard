Lesson 4 of the Peashooter build

Memory that survives the session

Stage 1's other success criterion: a fact you tell Peashooter today should still be there next time, without you repeating it.

Why this matters

In Project Transformers, Zain's specialists keep working memory of your conventions and decisions — the whole point of a persistent specialist instead of a fresh chat every time. A coding specialist that forgets your stack between sessions is barely better than pasting context into a new tab each time.

Knowledge Hermes's built-in memory is two files: MEMORY.md (agent notes — conventions, decisions, recurring facts) and USER.md (facts about you specifically). Both live at ~/.hermes/profiles/peashooter/memories/ — note the memories/ subfolder; they are not directly in the profile root, which is easy to assume wrong (an assumption this build actually got wrong once, while checking). Hermes reads both into every new session automatically — no flag, no manual load.
Correction — clone-from carries memory too

Peashooter's memory wasn't empty going into this lesson. Checking the files above turned up real content about git-swap, an unrelated past Go CLI project, plus git identities and a stale provider note — none of it something anyone told Peashooter directly.

Cause: hermes profile create peashooter --clone-from default back in Lesson 1 clones the source profile's memory files along with its config, not just config. A cloned profile starts from the source's accumulated state, not a blank one. Fixed with hermes memory reset (asks for a typed yes) — Peashooter's memory is a clean slate as of this lesson.

Do this now

Skill — hands on

1. Start a session and teach it one real fact — something true about your actual stack or a convention you want remembered (not a throwaway test string; you'll get more out of this if it's something Peashooter should really know going forward):

peashooter

Tell it the fact directly, e.g. "Remember: I use pnpm, not npm, for all my JS projects" — or whatever's actually true for you. Then exit the session (Ctrl+D, or however you normally leave a Hermes chat).

2. Start a completely new session — a fresh process, not --continue:

peashooter

Ask a question that needs the fact without restating it — e.g. "what package manager do I use for JS projects?" if that's what you told it. You're testing recall, not re-teaching.

3. Confirm it actually hit disk, not just the live session:

cat ~/.hermes/profiles/peashooter/memories/MEMORY.md

Your fact should be in there in some form.
