Lesson 34 of the Stage 5 build

A scheduled script checks four rules, and speaks only when one breaks

Record 0043, 0044, 0045, and 0046 each produced a check command that a person had to remember and run by hand. This lesson combines those four checks into one script, roster-audit.sh. A cron job runs the script every day. The script follows one rule. When every check holds, the script prints nothing. When one check fails, the script prints exactly one line naming the broken rule.

A check nobody remembers to run

Knowledge

Each record above named a rule that broke once. Each record also produced a check command Jokot could run by hand. A command run by hand works only when somebody remembers it. A scheduled command needs no memory, because the machine runs it every day without a request.

This script obeys one design rule. When every check holds, the script prints nothing. When one check fails, the script prints exactly one line for that check. Silence is the pass result. A delivered message always names a real defect.

Three facts about cron

Knowledge
  • The scheduler runs inside the gateway process. It checks the clock once every 60 seconds.
  • The flag --no-agent skips the model, so a job created with it costs no tokens.
  • The help text for hermes cron create states the rule in four words: Empty stdout = silent.

The script in full

Skill — hands on

Write this file at ~/.hermes/profiles/crazydave/scripts/roster-audit.sh. Copy every line, including every comment:

#!/usr/bin/env bash
# Check four roster rules. Print one line for each rule that fails. Print
# nothing when every rule holds, so a healthy run delivers no message.
#
# Each check names the learning record that found the defect.
set -uo pipefail

# 1. Every profile speaks into the same room. Record 0043.
n=$(grep -h '^TELEGRAM_HOME_CHANNEL=' "$HOME"/.hermes/profiles/*/.env 2>/dev/null \
      | sort -u | wc -l | tr -d ' ')
[ "$n" = "1" ] || echo "home channel: $n distinct values across profiles, expected 1"

# 2. The allowlist of Crazy Dave holds exactly three entries. Record 0046.
n=$(hermes -p crazydave config get command_allowlist 2>/dev/null | grep -c '^- ')
[ "$n" = "3" ] || echo "allowlist: crazydave holds $n entries, expected 3"

# 3. Crazy Dave keeps the kanban toolset. Record 0044.
hermes -p crazydave config get toolsets 2>/dev/null | grep -q '^- kanban$' \
  || echo "toolsets: crazydave is missing kanban"

# 4. No Telegram session runs on a prompt older than 7 days. Record 0045.
for db in "$HOME"/.hermes/profiles/*/state.db; do
  p=$(basename "$(dirname "$db")")
  old=$(sqlite3 "$db" "SELECT COUNT(*) FROM sessions WHERE source='telegram'
          AND ended_at IS NULL
          AND started_at < strftime('%s','now') - 604800;" 2>/dev/null)
  [ -n "$old" ] && [ "$old" != "0" ] \
    && echo "session: $p holds $old telegram session(s) older than 7 days"
done
exit 0

What the first run found

Knowledge

The script above was tested against the live machine on 17 September 2026, before any cron job existed. That run printed exactly one line:

session: sunflower holds 3 telegram session(s) older than 7 days

The audit found a real defect on its first run, on that date. The defect is still open. Sunflower holds four open Telegram sessions. The three that this script counts started on 9 September 2026, on thread NULL, thread 1, and thread 2. The fourth session serves #Planning, which is thread 3, and it started on 10 September 2026.

Read that list once more, because it carries the trap. The /new message of Lesson 33 ends the thread 3 session, and this script never counted that session. The three counted sessions stay open. A reader who completed Lesson 33 therefore still sees the same line today.

This result is correct behavior, not a defect in the script. The rule of record 0045 is broken on the real machine, and the audit says so every morning until somebody ends those three sessions.

Install and test

Skill — hands on

Install the script under Crazy Dave's scripts folder, then make it executable.

mkdir -p ~/.hermes/profiles/crazydave/scripts
chmod +x ~/.hermes/profiles/crazydave/scripts/roster-audit.sh
~/.hermes/profiles/crazydave/scripts/roster-audit.sh; echo "exit=$?"

Expect exit=0. Expect the one line above if Sunflower's old sessions still exist. Expect no line at all if Lesson 33 has already ended them.

This folder is not the obvious choice. The command hermes -p crazydave sets HERMES_HOME to ~/.hermes/profiles/crazydave. A cron job resolves --script under $HERMES_HOME/scripts. The job never resolves --script under ~/.hermes/scripts/. Lesson 17 already removed a file from this same folder. The course has met this folder before. The report script of Lesson 32 stays at ~/.hermes/scripts/hermes-report.sh. A soul file calls it by its full path. No cron job resolves it. The two scripts live in different folders for this reason.

A broken check that stays silent during this test is not ready for a cron job.

Create the cron job

Skill — hands on 
hermes -p crazydave cron create '0 9 * * *' \
  --name roster-audit \
  --script roster-audit.sh \
  --no-agent \
  --deliver telegram

The validator behind --script rejects an absolute path. The validator also rejects a leading tilde. A bare filename is the only legal value. That filename resolves under $HERMES_HOME/scripts. The command hermes -p crazydave sets HERMES_HOME to ~/.hermes/profiles/crazydave. Step 5 above already installed the file at that location for this reason. Run hermes -p crazydave cron list and report the stored value.

Force one run today

Skill — hands on

A daily job proves nothing today. Force one run now.

hermes -p crazydave cron run roster-audit
hermes -p crazydave cron runs <job id>

The first command runs the job immediately. It accepts the name, because cron run resolves a name to an id through resolve_job_ref.

The second command does not accept the name. It passes the value straight to an SQL filter on the job_id column, so a name matches no row and the output reads No cron execution attempts recorded. Use the 12-character id that cron create printed, or read the id from cron list.
