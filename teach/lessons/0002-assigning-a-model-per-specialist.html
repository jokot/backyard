One agent, one model choice

Why Zain runs different agents on different models, and giving Peashooter its own before we give it a personality.

(Small reorder from what Lesson 1 promised: we're assigning a model before writing SOUL.md, not after — you need a working model to actually talk to Peashooter and hear its personality, so that comes first.)

Why per-agent model choice matters

From the same Project Transformers post: Zain's coordinator ("Optimus") runs on his most capable model, because it has to reason well across every domain. His narrower specialists run on cheaper models where the task doesn't need top-tier reasoning, plus free-tier models from other tools where available. Result: he reported cutting costs to roughly 15% of baseline after the first week — not by using a worse assistant, but by matching model cost to what each agent's job actually demands.

Knowledge This works because a Hermes profile carries its own model/provider setting, independent of every other profile. Peashooter can run one model while a future specialist runs something cheaper for lower-stakes work — same isolation mechanism from Lesson 1, applied to cost instead of just memory.

(Updated after Lesson 2 shipped: we asked about reusing a personal Claude/Cursor subscription here. Short version — Hermes can technically do OAuth reuse of a personal Claude subscription, but that's a greyer usage-terms area than paying for API access directly, and Cursor's subscription isn't reachable by any third-party tool at all. We switched to an aggregator instead — see below — which also directly answers "I want to pick the model per bot, including cheap Chinese-lab options.")

The aggregator: OpenRouter

OpenRouter is one API key that reaches dozens of providers — Anthropic, OpenAI, DeepSeek, Qwen, Zhipu (GLM), Moonshot (Kimi), MiniMax, and more — billed per use, at each provider's own rate. It's already a first-class Hermes provider (it shows up in hermes auth add --help's own examples, and hermes doctor checks it directly). That's what gives you "pick the model per bot" with real freedom: Peashooter can run a frontier model for hard problems today, and something far cheaper for routine tasks tomorrow, without opening a new account each time.

Do this now

These steps touch a secret API key, so run them yourself in your terminal rather than pasting the key anywhere in chat.

Skill — hands on

1. Get a key: create one at openrouter.ai/keys. Add a small amount of credit — this is pay-per-use, not a subscription.

2. Make Peashooter the active profile, then run the picker:

hermes profile use peashooter
hermes model

Choose OpenRouter as the provider. If no key is configured yet, Hermes prompts you directly: OPENROUTER_API_KEY (or Enter to cancel): — paste your real key there. That prompt is the mechanism; it's what actually gets read later, not a separate step.

Correction An earlier version of this lesson had you run hermes auth add openrouter --type api-key first. Skip that — it stores the key in a different credential pool that hermes model and hermes doctor don't actually read for OpenRouter. They read the OPENROUTER_API_KEY prompt above instead. If you already ran the old command, it's harmless, just unused — nothing to undo.

Then browse the model list. For a coding specialist, a solid default is a mid-tier general model to start (change it any time with the same command) — worth noting where DeepSeek, GLM, Kimi, and MiniMax show up, since those are the cheap options you asked about; check OpenRouter's own pricing page for current rates before picking one for real work, since they shift over time.

3. Confirm it stuck:

hermes profile show peashooter

The Model line should now show what you picked instead of a blank.
