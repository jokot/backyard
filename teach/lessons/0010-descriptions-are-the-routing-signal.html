Lesson 10 of the Stage 2 build

The one line an LLM reads to pick a specialist

Every earlier lesson set up how a profile behaves once it's chosen. This lesson sets up how it gets chosen at all — the short description each profile carries, which is the only thing the kanban decomposer sees before it decides who does the work.

What actually reads this text

Knowledge

hermes kanban decompose — coming in Lesson 14, but the mechanism is worth understanding now — fans a rough task out into a graph of child tasks and routes each one to a profile. Its system prompt, built in hermes_cli/kanban_decompose.py's _build_roster() and _format_roster(), hands the LLM exactly this, one line per profile:

  - peashooter: Coding and engineering specialist
  - sunflower: Brainstorming, planning, task breakdown, and writing PRDs, proposals, and specs

That's the whole signal. Not SOUL.md, not memory, not skills — one line of text per profile, decided once and reused for every routing decision after. A profile with no description still appears in the list, tagged ⚠ undescribed, and the LLM is left guessing from the profile's name alone. A vague description like "Coding and engineering specialist" routes better than nothing, but worse than text that names the actual domain.

A correction, made in front of you

Correction — the planned commands were wrong

This lesson's plan assumed hermes profile describe <name> --description "..." and hermes profile list to check the current values. Neither is right. Reading hermes_cli/subcommands/profile.py's real argument parser: the flag is --text, not --description. And running hermes profile list directly shows this table — no description column at all:

 Profile          Model                        Gateway      Alias
 ───────────────    ───────────────────────────    ───────────    ───────────
  default         —                            stopped      —
  peashooter      deepseek/deepseek-v4-flash   running      peashooter
 ◆sunflower       z-ai/glm-5.3-flash           stopped      sunflower

To read one profile's current description, run describe with just the profile name and no flags — it prints the text alone, nothing else:

hermes profile describe peashooter
hermes profile describe sunflower

Do this now

Skill — hands on

1. Check both current descriptions with the read form above. Sunflower's was set at creation back in Lesson 7 and should already print:

Brainstorming, planning, task breakdown, and writing PRDs, proposals, and specs

Peashooter's, carried over from Stage 1, should print something shorter — a label, not a routing signal:

Coding and engineering specialist

If both already print exactly this, skip to Step 3 — Sunflower needs no change.

2. Sharpen Peashooter's description to match its own SOUL.md domain line (~/.hermes/profiles/peashooter/SOUL.md:4), so the same words that bound what Peashooter answers also drive what gets routed to it:

hermes profile describe peashooter --text "Software engineering: code review, debugging, architecture, tooling, build and dependency issues, technical writing about code"

3. Verify both again:

hermes profile describe peashooter
hermes profile describe sunflower

Peashooter should now print the sharpened text from Step 2. Sunflower's should be unchanged from Step 1.

There's also an --auto flag, which asks the auxiliary LLM to write the description instead — worth knowing about for a future profile, but not used here. Both descriptions above are hand-written on purpose: they quote the same domain line each profile's own SOUL.md already commits to, so the routing signal and the scope boundary never drift apart.

Why does a profile with no description still show up in the decomposer's roster, tagged "⚠ undescribed," instead of being left out?

Right — _build_roster() always includes every profile; an undescribed one just loses its best signal, it isn't dropped from the routing choice entirely.

Not the reason — this is specific to the decomposer's roster prompt, not a general Hermes requirement.

The tag reflects a real difference — an undescribed profile genuinely gives the LLM less to route on, not just a warning label.
