Lesson 30 of the Stage 4 build

A banned skill that is still installed is a ban in prose

Torchwood carries twenty five skills. One of them is kanban-worker, for the job its soul file forbids. Another is brainstorming, which its soul file bans by name. Both sit on disk, because --clone-from copied the skill kit of Peashooter and no lesson cut it. This lesson cuts it, and adds the seventh decision to the roster pattern.

How the gap opened

Knowledge

Every earlier profile had this step. Lesson 9 cut the kit for Peashooter and Sunflower. Lesson 13 cut it for Crazy Dave, and removed devops/kanban-worker by name, because a coordinator never runs a task itself.

Stage 4 cloned a profile that had already been cut, so the kit looked finished. It was finished for a worker that writes code. Count the difference:

hermes skills list -p crazydave --enabled-only
hermes skills list -p torchwood --enabled-only

Crazy Dave reports 0 enabled. Torchwood reports 24 enabled, and a twenty fifth skill hides behind environments: [kanban], which is why kanban-worker never appears in that list and still loads.

This is the seventh decision of the roster pattern. The six in the reference document all set what a profile is. This one sets what a profile knows how to do, and a clone inherits it whole.

Why prose is not enough here

Knowledge

The soul file of Torchwood already carries this sentence:

Do not use the brainstorming skill. It ends by writing a design document
and by invoking another skill, and you write no file.

The skill is still installed, and the list above reports it as enabled. Record 0015 states the rule: set the limits from the implementation, not from the conversation. A deleted directory is a limit. A sentence about a directory is a request.

This one is cheap to convert, which makes it different from the read-only limit of Lesson 28. Nothing in Hermes stops a write, so that gap stays open until Stage 5. A skill kit is a set of directories, and rm -rf closes it today.

A second cost is measurable. Every enabled skill puts a name and a description in the prompt, and a model that sees a relevant name reads the file. That is one turn spent on instructions the profile must not follow. You already watched it happen once.

Do this now

Skill — hands on

1. Record the count before the cut.

hermes skills list -p torchwood --enabled-only | tail -1

Expected: 24 enabled shown. Write the number down. The check after the cut compares against it.

2. Delete every category except one. Torchwood keeps ste-writing, because its soul file permits that one skill and no other.

cd ~/.hermes/profiles/torchwood/skills

# Kits for a profile that writes files
rm -rf brainstorming code-review codebase-design devops domain-modeling \
       github improve-codebase-architecture resolving-merge-conflicts \
       software-development

# Category directories the Peashooter cleanup left empty
rm -rf apple autonomous-ai-agents creative data-science email media \
       mlops note-taking productivity research smart-home social-media

3. Check what survived.

ls ~/.hermes/profiles/torchwood/skills/
hermes skills list -p torchwood --enabled-only | tail -1

Expected: one directory named ste-writing, plus the dot files that track the kit, and 1 enabled shown.

4. Restart the gateway. The skill list reaches the model through the prompt, so the running process still offers the old one.

hermes -p torchwood gateway restart

5. Repeat the request that exposed this. Post a task in the Prompts topic and watch the first lines of the reply. Expected: no Reading skill line for kanban-worker and none for brainstorming.

Before you run step 2

These directories are copies. The bundled kits live in ~/.hermes/skills/, and the local kits, including ste-writing and brainstorming, still exist under ~/.hermes/profiles/peashooter/skills/. Check that before you delete:

ls ~/.hermes/skills/
ls ~/.hermes/profiles/peashooter/skills/

A restore is one cp -r from either path. Run the two listings first, so the claim in this box is a fact you saw and not a sentence you trusted.

The seventh decision

Knowledge

The reference document now holds seven rows. The new one reads:

DecisionWhere it livesTorchwood
Skill kit The skills/ directory of the profile ste-writing only, everything else deleted

The trap is specific to cloning. A clone of a cut profile looks cut. The kit that survived the earlier cut is the kit of the earlier role, so check the count and not the appearance.

Torchwood's soul file bans the brainstorming skill, and the skill is still installed. What have you built?

Right. Record 0015 draws the line there: a limit that the implementation does not carry is a limit the model may miss.

Delivery is not enforcement. The read-only rule of Lesson 28 reaches the model on every turn too, and Lesson 29 states plainly that it proves nothing.

An installed skill is offered in the prompt by name and description. The model reads one whenever the name matches the request.

Why does kanban-worker stay absent from --enabled-only and still load?

Right, and Lesson 13 hit the same thing with kanban-orchestrator, which is why Crazy Dave reports zero enabled skills and still coordinates.

The clone copies files and sets no flag. Every other copied skill in that same kit reports itself as enabled.

The listing counts thirteen builtin skills for this profile. Source is not what hides it.
